# Skill Index

Skills are focused procedures, not architecture authority. Load at most one by default; a task that genuinely needs more must explain why.

| Skill | When to load |
|---|---|
| `skills/web_api_wrapper_skill.md` | Adding or materially changing a browser API wrapper |
| `skills/js_bridge_skill.md` | JavaScript value/object/closure, promise, callback, or wasm bridge work |
| `skills/event_handling_skill.md` | Event wrappers or listener registration/removal/options work |
| `skills/dom_tree_manipulation_skill.md` | DOM elements, hierarchy, mutation, attributes, document/window work |
| `skills/css_composition_skill.md` | Typed CSS values/properties/rules or serialization work |
| `skills/documentation_sync_skill.md` | Durable architecture/navigation/task/decision/debt knowledge changed |
| `skills/patch_review_skill.md` | Reviewing a concrete patch or change set |

Do not create a new skill until repeated work exposes a stable reusable procedure not already covered by an owner, checklist, or existing skill.
